# **1. 目的**

個人のパーソナルトレーナーが

セッション提供後に未収金を意識せず、指導に集中できる状態を作るため、

請求確定および請求通知を自動で行う。

本設計は 「請求確定＋初回請求通知」 のみを対象とする。

# **2. 対象ユースケース**

トレーナー側の業務フロー（セッション完了等）を起点として、

請求が自動的に確定され、顧客に請求通知が送信される

# **3. スコープ**

**3.1 本設計に含めるもの**

- 請求確定要求の受付
- 請求データの生成・確定
- 請求データの永続化
- 請求通知（メール）の送信

**3.2 本設計に含めないもの**

- 金額計算ロジック
- セッション管理・指導中機能
- 支払い処理（決済）
- 未収判定・督促・再通知
- 請求内容の編集・修正

# **4. 前提条件（不変）**

- 請求は「金と責任の記録」であり、業務状態は管理しない
- 請求確定後、金額・期限・対象は変更しない
- 請求確定と通知送信は分離する
- 通知失敗時でも請求は確定済みとする
- 請求対象は汎用IDで扱い、業務種別は解釈しない

# **5. 責務定義（レイヤ2）**

**5.1 請求確定を指示する責務**

- 起点側業務フローから請求確定要求を受け取る
- 入力データの最低限の妥当性を確認する
- 請求生成・確定処理を呼び出す

**5.2 請求を生成・確定する責務（中核）**

- 請求IDを発行する
- 請求情報を生成する
- 請求を「確定」状態として扱う

※ 業務的な意味（セッション・予約等）は解釈しない

**5.3 請求通知を送る責務**

- 確定済み請求情報をもとに通知を送信する
- 通知結果は請求状態に影響させない

# **6. 入力データ仕様（請求確定要求）**

起点側業務フローから、以下の情報が渡される。

| **項目** | **説明** |
| --- | --- |
| customerId | 請求対象の顧客ID |
| billingTargetId | 請求対象を示す汎用ID |
| billingTargetType | 対象種別（例：SESSION / RESERVATION） |
| billingAmount | 請求金額 |
| paymentDueDate | 支払期限 |

※ 金額計算は起点側の責任

※ 請求側では再計算・精査を行わない

# **7. 請求データ仕様（確定時に固定）**

請求確定時、以下の情報を固定する。

| **項目** | **説明** |
| --- | --- |
| billingId | 請求ID |
| customerId | 請求対象顧客 |
| billingTargetId | 請求対象ID |
| billingTargetType | 対象種別 |
| billingAmount | 請求金額 |
| paymentDueDate | 支払期限 |
| billingStatus | UNPAID |
| billingConfirmedAt | 請求確定日時 |

# **8. 処理フロー**

**8.1 全体フロー**

起点側業務フロー

↓ 請求確定要求

請求確定受付

↓

請求生成・確定

↓

請求Repository（INSERT）

↓

請求通知送信

**8.2 詳細フロー**

1. 起点側から請求確定要求を受信する
2. 必須項目（顧客ID・金額・期限）の存在を確認する
3. 請求IDを採番する
4. 請求データを生成し、確定日時・未収ステータスを設定する
5. 請求データをDBに保存する
6. 保存済み請求情報をもとに請求通知を送信する

# **9. エラーハンドリング方針**

- 請求生成・保存失敗時
→ 処理を中断し、請求は確定しない
- 通知送信失敗時
→ 請求は確定済みとし、エラーのみ記録する

# **10. 将来拡張を想定した設計ポイント**

- 請求対象は汎用ID＋種別で保持しているため、
    - セッション
    - 予約
    - その他業務
    に拡張可能
- 
- 金額算出ロジックは請求責務に含まれていないため、
    - Strategy
    - Factory
    による後付けが可能
- 

# **11. 設計方針まとめ**

- 請求は業務を知らない
- 請求は金額を決めない
- 請求は「確定」を責務とする
- 境界は契約（入力データ）で守る
